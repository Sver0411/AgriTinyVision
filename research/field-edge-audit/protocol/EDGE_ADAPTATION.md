# Target-labelled edge-head adaptation on FGVC7

This second experiment assumes that a deployment can obtain disease labels for selected Cornell photographs. It uses a fixed test set for all budgets, methods and seeds. It measures software adaptation of the released floating-point AgriTinyVision graph. The cached tensors and packed replacement heads are independently inspectable. The historical board experiment addresses different data and weights.

## Prespecified split and estimand

1. Form connected components over all 1,821 photographs using 64-bit perceptual hash Hamming distance at most four. The hash uses grayscale at 32 × 32 pixels, an orthonormal 2D DCT, and the upper-left 8 × 8 block thresholded by the median of its 63 non-DC entries. A file SHA-256 match also joins components. Remove an entire component if its healthy/diseased labels conflict or any member appears in the archived cross-corpus overlap table.
2. For each eligible component retain the image with the lexicographically smallest SHA-256 of the ASCII string `FGVC7/representative/v1|` followed by the relative image path. Break digest ties by the path. Sort representatives by a second independent digest from `FGVC7/split/v1|` followed by the path. The first floor(number of representatives / 4) form the candidate label pool. All others form the test pool. File-path hashing approximates an image-group random split within this one orchard dataset. Orchard, photographer and collection-session IDs are unavailable for geographical or temporal blocking.
3. For each seed 0 through 19, draw a NumPy PCG64 permutation of candidate indices with seed 20261127 + seed. Train on the first 8, 32 or 128 labels. Methods use identical rows and budgets are nested. Never rebalance labelled image draws. The evaluation population comprises the retained test representatives with their release labels. Report balanced accuracy, accuracy, sensitivity and specificity. Variation across seeds describes training-subset variation conditional on this shared holdout.

## Heads and features

The frozen AgriTinyVision software path resizes each field image directly to its released 160 × 160 RGB input. The original threshold is SUSPECT probability at least 0.30, ignoring the separate quality rejection to define binary decisions for every image. The one-dimensional baseline fits logistic regression to the original suspect minus normal logit. TinyVision adaptation uses the 1,280 input coordinates of the released final Gemm. DINOv2-small uses its 384-dimensional CLS embedding after processing the bytes of a quality-75 JPEG with long edge 224. All vector fits use unit L2 norm and a zero-vector guard. The scalar baseline retains its native logit scale.

All fitted heads use scikit-learn binary L2 logistic regression with balanced class weights, C=1, liblinear, penalized intercept (intercept scaling 1), tolerance 1e-8, maximum 3,000 iterations and no tuned parameter. If a draw contains one class the head has zero weights and fixed signed intercept 1 or −1 matching that class. Each fitted decision uses signed score at least zero for disease. Replication uses little-endian disjoint records.

* Local INT8 quantizes each activation using a separate maximum-absolute scale and rounds to nearest even into [−127,127]. Train on the L2-normalized reconstruction of the actual encoded calibration packet. Quantize fitted weights using a single symmetric float32 scale. The deployed scoring rule uses an INT32 dot and squared norm, double-precision square root and the transmitted float32 weight scale and bias. The local feature scale cancels under L2 normalization.
* Local FP32 transmits the original float32 activation for the same photos. Fit on L2-normalized values and serialize the coefficient vector and bias as float32. Scalar calibration uses the measured one-dimensional float32 margin. The remote comparator fits another float32 head, on features from the same target-label subset and same actual JPEGs used in inference. The remote head stays at the server. The frozen baseline has zero labels, updates, and communication.

## Application bytes and availability of labels

Here training happens on a service which has no access to target originals. Upload one labelled record per calibration example. A nine-byte header (four-byte magic, four-byte numeric image ID, one-byte diagnosis) precedes the native float32 margin, the float32 feature vector, the compressed activation (four-byte float32 scale plus INT8 samples), or the remote JPEG. Signed INT8 replacement heads contain a 14-byte little-endian header (magic, uint16 dimension, float32 weight scale, float32 intercept) followed by one byte per coefficient. A floating-point replacement head contains a 10-byte header (magic, dimension, bias) and four bytes per coefficient. The frozen head is already installed. Reopen the archive and score each test decision with a decoded head.

Locally informed labels cover field staff or previously available annotations. A second scenario obtains labels from a remote human. An additional frame is sent with eight bytes of framing and the actual 224-JPEG bytes. The reviewer and trainer are colocated and share the stable image ID. Where the remote training design already uploads JPEGs the same bytes serve both purposes. Edge training still transmits original-input activations or logits because the lossy long-edge JPEG does not reproduce those tensors. The administrative task of requesting and joining a label uses the stable ID. In the remote-review scenario the record reserves the same one-byte diagnosis field with value 255 for unknown. The colocated server attaches the human diagnosis by ID after review. No need arises to return the human label to the device. The additional remote-review JPEG therefore provides a conservative additive cost for the edge strategies. Label count measures human demand separately. These totals describe an application protocol with no measured radio/transport headers, retries, research artifact ZIP packaging, or training-label labour time. For all-remote inference upload the actual independent test-set JPEG per image with an eight-byte identifier record; return a 12-byte ID and float32 score record. Edge predictions require no subsequent upload. Total communication depends on how many future images are processed.

The source-pixel work, DINO preprocessing and full-precision prediction use an ONNX CPU runtime on the host. Only heads and their input wire format are adapted in this experiment. The evaluation provides neither an on-board INT8 backbone run, field deployment latency, nor plant-level external validation.

## Reproduction and outputs

From the project root, prepare the pinned target sources, the released TinyVision model, and both target image manifests as described in the dataset documentation. Obtain the source activations with `python scripts/edge_adaptation_features.py` and the remote JPEG embeddings with `python scripts/field_specialist.py fgvc`. Then run `python scripts/edge_adaptation.py`. An existing raw JPEG archive may be selected with `--jpeg-dir`. The experiment verifies every archived JPEG's digest and byte length against the DINO extractor manifest. Python 3.12 dependency versions are in the results manifest. Reproduce the wire-format edge cases with `python -m unittest discover -s tests -p 'test_edge_adaptation.py'`.

The prefix `results/edge_adaptation_` identifies the outputs. The split CSV lists each source image, component and inclusion status. The metrics CSV gives confusion counts and communication costs per seed, budget and method. The summary CSV reports mean and range across the 20 training draws. The predictions NPZ stores the exact sorted held-out paths, all nested training paths, test labels and dense score/decision arrays with dimensions seed, budget, method and test image. Consult its `seeds`, `budgets` and `methods` arrays for axis labels. Frozen scores are suspect probabilities, while the fitted heads return signed logits. The heads ZIP contains four portable model blobs per seed and budget, with numeric values decoded as little-endian. The manifest records both verified input feature archives, test population, library versions and reproduction errors.

In the completed comparison, the 1,353 test photographs include 377 healthy and 976 diseased examples. The candidate label pool contains 128 healthy and 322 diseased examples. The 8-label draws contain two one-class subsets. Their constant classifier is included in the reported results. The 32-label INT8 head obtained mean sensitivity 0.862 and specificity 0.685, compared with 0.965 and 0.430 for the released frozen head. The mean gain in balanced accuracy coexists with a small decline in raw accuracy at this budget. At 128 labels the mean INT8 balanced accuracy was 0.800 and raw accuracy was 0.827. The same-label remote DINO head achieved 0.845 balanced accuracy. All means describe label-set resampling on one fixed test population.
