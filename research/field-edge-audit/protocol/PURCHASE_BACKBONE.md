# Source score separation and the alarm threshold

This exploratory diagnostic followed the completed acquisition comparison and responds to a question about the released checkpoint. Within each site, all pipelines use the same calibration and evaluation candidates as that comparison. The native cutoff is 0.30 for V2 and V2-grid and 0.50 for V4. Re-select only the cutoff by maximizing sensitivity plus specificity on the paid prefix of 16, 32 or 128 calibration references. Ties use the cutoff closest to the native cutoff, then the smallest exact observed candidate. If a class is absent, retain the original cutoff. The diagnostic reports an oracle on the evaluation references to show the maximum obtainable by moving a single threshold. It is a retrospective bound and does not enter any deployed score. Compare the fixed expert and a refitted 32-label head without routing. The threshold-only test changes the operating point while preserving AUC. The head test can change ranking as well. Neither test isolates architecture from training data.

Run `python scripts/purchase_backbone_diagnostic.py` after preparing the private cohort caches. The public result is aggregate across 20 draws.
