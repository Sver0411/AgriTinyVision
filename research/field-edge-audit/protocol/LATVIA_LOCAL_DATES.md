# Local calibration followed by date-held-out evaluation in Latvian scab photos

This protocol was frozen without inspecting any Latvia predictions or misclassification counts. It differs from applying a previously selected Cornell rule to the entire natural archive. The local experiment uses some Latvian sick/healthy source labels to calibrate its decision policy. Positive means publisher-labelled scab and negative means no visible scab according to that release. Other causes of damage or disease are outside this reference definition.

## Cohort and chronological split

Use the 1,190 source records indexed by their original relative archive paths. A calendar day is established solely from a valid original EXIF DateTimeOriginal field, with no fallback to an upload date, ZIP timestamp, arbitrary row order, or inferred date from a disease class. Missing or invalid timestamps are excluded. Date denotes a capture day and does not identify an orchard, a tree or a leaf. The source release is not sampled at random from either diseased or nondiseased Latvian foliage.

Before designating either pool, form connected components over all 1,190 photos using matching original file SHA256 or 64-bit perceptual hash Hamming distance at most four. The pHash uses the project’s grayscale 32×32 orthonormal DCT and non-DC median protocol. Exclude all members of any component containing more than one observed capture date. Keep same-day duplicates together. Exclude a whole component if its source scab labels conflict. Missing-date members cannot enter either pool. This rule prevents connections through an undated image from bridging two capture days. Record all exclusions and the date-by-class counts.

Sort the remaining unique dates chronologically. With G distinct eligible days, use the earliest floor((G+1)/3) complete days as the calibration pool and every later eligible day as the holdout. This fixes approximately one third of days for calibration, regardless of the resulting number of images. Stop without calibration/evaluation if there are fewer than three eligible days or either pool has zero scab or zero non-scab references. Days that contain a single source class remain in the selected pool. Never move a date to improve support or resulting performance. The local chronology need not represent independent seasons or orchards; counts describe these retained photos.

## Decision and reporting

Use precisely the 475 rules, component actions, inclusive/strict cutoffs, preference order and fallback of the sealed Cornell protocol `DUAL_DIRECTIONAL.md`. Fit solely on the calibration days. Precompute label-independent edge and expert scores once from the published graphs as part of the blind feature archive. Store the selected local 22-byte rule and metadata before loading test labels for scoring. If the calibration pool permits no strict improvement, use the predeclared original-policy fallback. Report frozen-edge, transported Cornell policy and locally calibrated policy on exactly the same later-day photos. Report FP, FN, original correct/false alerts influenced by each branch, confusion counts by calendar date, upload fraction, source JPEG byte counts and the additional one-time local label/calibration and model-update bytes. The original Cornell rule over all 1,190 photos is a separate external analysis. The local later-day set remains only one geographical archive, and all test-set labels are withheld from rule selection.

No alternate date split, grid, near-duplicate criterion, additional model or second threshold pass will be tried after the test outcome. The app-level byte model is the same as the Cornell rule. The blind feature archive records actual byte counts after real long-edge-224 JPEG serialization at quality 75; each upload includes the same request and response headers. The local calibration pool supplies one class bit carried in one byte, the original edge probability, image ID and the JPEG for every labelled example.
