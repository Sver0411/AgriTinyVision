# Single-pass review under a byte allowance

This follow-up responds to a deployment critique after inspecting the earlier batch results. We fix the following methods before scoring their streaming trajectories. They use existing Cornell labelled draws containing 32 or 128 records, the exact existing heads, the fixed server, and the remaining cohorts, at 10%, 25% and 50% nominal byte allowances. Calibration location is either at camera or at remote reviewer. A camera label needs its measured activation packet plus the installed head. A remote label also needs the original measured calibration JPEG and application header. The experiment measures bytes and finite-cohort decisions. It assumes the source calibration images were collected before this deployment and excludes human annotation waiting time.

## Exogenous quota and orders

Use exactly the existing first 32 Cornell calibration IDs in each seed to estimate mean complete JPEG request/reply size μ. Both label budgets therefore inherit the same μ. No target-test image byte length, score or label sets the allowance. An announced service window of N arrivals has a fixed external allowance B=floor(N × μ × q) with q=0.10, 0.25 or 0.50. The variable size of target photographs makes q relative to the source planning estimate. Report the realized relationship to full transmission of the target corpus. A second operational policy receives qμ credits at each arrival, with no advance knowledge of N or B available to the policy. Its prefix consumption can never exceed the credits earned.

Latvia uses the original EXIF DateTimeOriginal on all 1,190 photos, sorted chronologically. Tied timestamps use a salted opaque hash of source bytes, with an opaque identity hash only to disambiguate exact copies. A fresh EXIF audit of the actual evaluation images found zero DateTimeOriginal tags in each of Cornell (1,353 JPEGs) and Kashmir (384 processed images). Neither release supplies a verified complete acquisition sequence for those photographs. Use five deterministic opaque permutations of original content IDs at these sites and show the range over them. Synthetic orders represent uncertainty about arrivals, not observed camera time, burst timing or prevalence drift. Paths never break equal-score or equal-time ties lexicographically.

## Policies

The unmodified camera and the adapted signed-byte head each run a fixed-gate policy and a causal pacing policy. Their urgency is 1 minus |original disease probability − 0.30|/0.70, or 2 sigmoid(−|adapted margin|) respectively. Both rankings equal the original batch project's rankings. The training service estimates a cutoff from calibration scores and measured JPEG sizes. Adapted calibration scores are predicted out of fold with up to four stratified folds inside the existing draw. Deployment uses the final model fitted on all allowed labels. Only one 12-byte packet (magic, binary32 urgency cutoff, binary32 initial mean JPEG request/reply size) is returned for a streaming gate. The unsupervised gate for a frozen camera uses unlabelled calibration scores and lengths. This setup is charged explicitly.

For an announced budget, installation occurs before the first image if the complete head/gate setup fits. Otherwise the system gracefully falls back to the frozen camera with the same form of streaming gate. Choose the fixed urgency cutoff to approximate the desired remaining bytes per arrival on the calibration images; preserve source score ties. The fixed-gate policy checks the cutoff and remaining budget at the current arrival. It never rearranges images. In the paced policy, after each arrival the desired acceptance fraction is the remaining bytes divided by remaining announced slots times the running complete JPEG cost estimate. Update the threshold by 0.05 times the difference between actual threshold passage (0/1) and the desired fraction, clipped to [0,1]. Smooth the mean observed JPEG cost of encoded candidates using a 0.05 update. Both steps use only the current observation and the prefix. A short fixed window can therefore be budgeted without future feature or image storage.

With no announced horizon or initial credit, a third policy accumulates its per-capture credit until the complete setup fits. It uses the released edge model alone while saving, and enables the chosen camera model and gate at that arrival. It never asks how many frames remain. After activation, cap saved short-term credit at four initial expected image costs. Update the threshold as above with desired acceptance qμ/current estimated cost, and send only eligible frames that can be paid from current credits. Report the activation frame and the cases where it never occurs. This is an intentionally strict cold start. It does not impute free remote labels to the first frames. A fixed-camera credit policy pays just the 12-byte gate and provides the fair no-update control.

A batch comparator using global score sorting receives exactly the same externally fixed quota and setup accounting (the global sorter needs no 12-byte gate). Its score ordering is unavailable to a single-pass router. The conditional peak memory figures count actually encoded, concurrently buffered JPEG payload bytes for the specified in-memory sender. The streaming sender holds at most one compressed payload; frames below its threshold need no JPEG. The batch implementation keeps the encoded batch while sorting (or could move it to storage). These figures exclude RGB input, codec/model workspace, parameter storage and separate historical calibration data. The image sender sees only current local information and its own state. Labels and cloud predictions enter offline evaluation after all query masks have been produced.

## Published methods under the same one-frame policy

This comparison uses the same 128 labels and source-planned fixed byte allowances. A separate shared streaming selector isolates how each published score orders photographs. For the first 16 arrivals it only collects local scores and emits the camera decisions. Afterwards, it computes the current score's midrank among the preceding 64 local scores, before seeing the remote answer. Its instantaneous funded fraction is remaining bytes divided by remaining scheduled arrivals and the running cost estimate. Send when the local percentile reaches 1 minus that fraction and the current JPEG fits. The cost update is the same 0.05 smoothing as above. The history contains at most 64 scalar scores, no images, labels or remote outputs. Rank and byte scheduling are changed explicitly from the papers. The separate original EdgeBoost operating-point arm uses its trained temperature and calibration cutoff in arrival order until the same hard ceiling is exhausted, with an 8-byte configuration fee. EdgeBoost rank-only mode uses its calibrated two-class top-two probability gap. Its temperature can be compiled out for percentile scheduling, requiring no extra downloaded bytes. Equality of the actually computed percentiles and query masks is enforced, in addition to the mathematical monotonicity argument. The learned full-feedback OvA, CompareConfidence and Mao scores use their balanced ports and exactly the transmitted startup byte costs from PUBLISHED_DEFER.md. If full installation is unaffordable, fall back to the same affordable ranked adapted head, then to the identical frozen-camera percentile gate. All options share N, allowance, order, JPEG encoding and server. Rank burn-in and historical scores never use evaluation labels.

## Replay and physical payload check

Run `python scripts/streaming_review.py` to rebuild calibration and held-out scalar scores from the local feature caches. Run `python scripts/streaming_review.py --replay results --out /tmp/stream-replay` with the portable score files to reproduce the decisions. The published-score comparison uses `python scripts/streaming_published.py --out /tmp/stream-published-replay`. Every output row joins on site and site-local row_index; bit masks unpack with `np.unpackbits(matrix, axis=1, count=len(y))`. The single-pass state is given only current local observations. The benchmark driver loads scalar arrays into RAM to replay many policies and orders, so the reported compressed-payload memory is a protocol accounting measure rather than Python process memory.

Run `python scripts/streaming_review.py --verify-payloads` in the full project to independently read each transmitted Cornell/Kashmir candidate JPEG and regenerate every Latvian JPEG from the licensed local archive. It compares both length and SHA-256 against the message fingerprints, releases each compressed payload before reading the next, and writes a per-site empirical checksum audit. Truth labels are not used in this audit. Frame timestamp support was checked in the raw Cornell and Kashmir images. File names and archive row ordering were never treated as acquisition times.
