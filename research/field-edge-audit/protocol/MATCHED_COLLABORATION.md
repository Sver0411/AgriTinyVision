# Matched single-model and collaborative controls

This additional comparison follows the request to separate the benefit of two-model decisions from the benefit of choosing a local cutoff. It is a retrospective comparison on previously reported cohorts. This document fixes the new single-model comparisons before executing their evaluation. The earlier dual-directional binary remains frozen. Its paired constituent scores are the deployed MobileNetV2 suspect probability and the source-balanced PlantDoc DINO probability.

## Data and decisions

Use the same 450 Cornell calibration photographs and labels for every tunable control. Apply the resulting cutoffs unchanged to the disjoint 1,353 Cornell test photographs, the 384 Kashmir photographs and the complete 1,190-photo Latvian collection. No test-set label enters fitting, operating-point selection or tie-breaking. External sites have different disease definitions. On Latvia the positive class is visible scab. The source audit was finalized before this comparison and did not inspect predictions.

Fixed controls use the published edge cutoff of float32 0.30 and the independent DINO cutoff of 0.50. For each tunable single score, evaluate every distinct observed float32 calibration probability with the inclusive `p >= threshold` decision, plus 0 and the first float32 value greater than 1. Sort the deduplicated thresholds ascending. These candidates include constant-positive and constant-negative decisions. Do not round continuous scores to a coarse grid.

Compute reference FP and FN from the published edge decision on those calibration labels. The primary target requires FN at most floor(reference FN/2) and strictly fewer FP and FN than the reference. Among feasible cutoffs, minimize FP, retractions relative to the reference, and FN in that order. Ties use the first cutoff in ascending order. Inference cost is constant within each single-model family. If the primary condition fails, restrict to cutoffs strictly reducing both counts and minimize FN, FP and retractions in that order. If that also fails, deploy the published edge decision and record the fallback explicitly. For the additional empirical Neyman–Pearson-style controls always deploy the selected single model. Require only FN at most floor(reference FN/2), minimize FP then FN, then retractions and cutoff order. This is a calibration constraint and carries no population error guarantee. The collaborative method replays the existing 22-byte dual-directional rule, checked against its recorded binary digest and Cornell calibration IDs. It is not refitted on test sites.

## Application-byte accounting

Charge calibration once on the same 450 locally labeled photographs. The fixed baselines have no target-calibration traffic. For edge-only threshold calibration the device sends only a 13-byte record per image (four-byte tag, four-byte integer ID, four-byte local probability, one-byte label). For DINO-only calibration the device sends each measured 224-pixel JPEG and a nine-byte header (four-byte tag, four-byte ID, one status byte packing the label and original edge decision). That original decision supplies the same calibration reference counts and retraction tie-breaks without a second score upload. Single-model tuning sends one four-byte float32 cutoff back to the device; a NaN sentinel requests the fallback to the published edge. The dual method follows the existing 13-byte calibration header plus the JPEG and returns its 22-byte rule. The 450 labels are treated as locally available; human annotation labor and any network used to obtain them are outside the ledger.

For deployment, local inference uses zero application bytes per image. Remote inference uses each actual 224-pixel JPEG plus an eight-byte request header and a 12-byte score reply; DINO-only uploads every image unless the primary control explicitly fell back to the published edge. A dual-direction request uses the same byte format for each image selected by the frozen gate. Report counts, sensitivity, specificity, balanced accuracy, calibration bytes, inference bytes and their sum, along with each individual decision and per-image inference bytes. These are application bytes measured or reconstructed from the actual payload lengths; no server or radio timing is inferred.
